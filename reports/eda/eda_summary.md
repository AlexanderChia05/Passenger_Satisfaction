## 1. Size and structure
- Train **103,904** rows, test **25,976** rows, 25 raw columns.
- Dropped as identifiers (no predictive meaning): Unnamed: 0, id.
- Remaining: 4 categorical (Gender, Customer Type, Type of Travel, Class), 4 numeric (Age, Flight Distance,
  Departure/Arrival Delay), 14 ordinal service ratings (0-5), 1 binary target.

## 2. Duplicates
- Duplicate rows in train: **0** (ignoring the target: 0); duplicate ids: 0.
- Passenger ids shared between train and test: **0**; identical rows across splits: 0.
- No leakage between splits from duplicated records.

## 3. Target balance
- Satisfied: **43.3%** train, 43.9% test; neutral/dissatisfied 56.7%.
- Mild imbalance (about 57/43), so no resampling. Stratified K-fold keeps the ratio in every fold, and
  F1, ROC-AUC and MCC are reported because accuracy alone flatters the majority class (the Dummy baseline already scores 56.1%).

## 4-5. Missing values
- Explicit NaN only in **Arrival Delay in Minutes**: 310 train + 83 test rows (0.30%).
- Hidden missing: rating **0 means "not applicable"**, not "very bad". Highest shares:
  Departure/Arrival time convenient 5.10%, Ease of Online booking 4.32%, Inflight wifi service 2.99%, Online boarding 2.34%.
- 7.9% of passengers have at least one 0 rating, so dropping them would lose data
  (8.2% incomplete overall).
- 0-rated passengers behave differently: e.g. Inflight wifi service = 0 -> 99.7% satisfied vs 43.3% overall,
  so "was a 0 given" carries signal.

## 6-7. Distributions
| Feature | Mean | Median | Std | Max | Skew | Share = 0 |
|---|---|---|---|---|---|---|
| Age | 39.4 | 40 | 15.1 | 85 | -0.00 | 0.0% |
| Flight Distance | 1189.4 | 843 | 997.1 | 4983 | 1.11 | 0.0% |
| Departure Delay in Minutes | 14.8 | 0 | 38.2 | 1592 | 6.73 | 56.5% |
| Arrival Delay in Minutes | 15.2 | 0 | 38.7 | 1584 | 6.60 | 56.0% |

- Delays are extremely right-skewed (skew ~6.7); more than half the flights have 0 delay. log1p brings them close to symmetric.
- Flight distance is moderately skewed (1.11); Age is symmetric (-0.00).
- Ratings (ignoring 0) centre on 3-4; mean rating ranges from 2.81 (Inflight wifi service) to 3.64 (Inflight service).

## 8. Outliers
- IQR rule flags Age 0.0%, Flight Distance 2.2%, Departure Delay 14.0%, Arrival Delay 13.4%.
- These are **genuine long delays / long-haul flights**, not data errors (all values within physical limits, no negatives).
  Satisfied rate with departure delay > 180 min: 36.0% vs 45.8% with no delay.
- Kept, not clipped: they are real passengers the model must score. log1p limits their leverage for
  distance-based models (KNN, SVM, MLP); trees are insensitive to them.

## 9-10. Correlation
- Departure vs arrival delay: Pearson **r = 0.965** (near-duplicate information).
- Strongest other pairs (Spearman):

| Feature A | Feature B | r |
|---|---|---|
| Departure Delay in Minutes | Arrival Delay in Minutes | +0.74 |
| Inflight wifi service | Ease of Online booking | +0.71 |
| Inflight entertainment | Cleanliness | +0.68 |
| Seat comfort | Cleanliness | +0.67 |
| Food and drink | Cleanliness | +0.65 |
| Baggage handling | Inflight service | +0.63 |

- Service ratings form correlated clusters (digital: wifi / online booking / online boarding; comfort: seat /
  entertainment / food / cleanliness). Moderate (< 0.8), so all are kept; ensembles, NCA and regularisation
  handle the redundancy. Feature-selection experiments (Experiment lab) confirm: all features F1 0.951 vs top-12 by MI 0.915.
- Strongest single correlates of satisfaction: Online boarding (+0.55), Inflight entertainment (+0.40), Seat comfort (+0.36), On-board service (+0.33).

## 11. Features vs target
- Class: Business **69.4%** satisfied vs Eco Plus 24.6% vs Eco 18.6%.
- Type of travel: Business 58.3% vs Personal 10.2%.
- Customer type: Loyal 47.7% vs disloyal 23.7%.
- Gender: Female 42.7% vs Male 43.9% - almost no signal.
- Interaction: business travellers in Business class are 72.0% satisfied,
  personal travellers in Eco only 10.2% - the basis of the rule baseline.
- Ratings with the biggest lift from score 1 to 5: Online boarding (+73 pts), Inflight wifi service (+67 pts), Inflight entertainment (+51 pts).
  Weakest: Gate location (+8 pts), Departure/Arrival time convenient (-6 pts) - not monotone, so trees/ensembles fit them better than a linear score.

## 12. Feature relevance (mutual information)
- Top: Online boarding (0.208), Inflight wifi service (0.160), Class (0.133), Type of Travel (0.113), Inflight entertainment (0.097).
- Lowest: Departure/Arrival time convenient (0.003), Gender (0.000), Departure Delay in Minutes (0.000).

## 13. Train vs test consistency
- Largest PSI: Online boarding = 0.0006; every feature < 0.1 (stable).
  The official test split is a fair hold-out; no re-splitting needed.

## Findings -> preprocessing decisions

| Finding | Decision (in `src/features.py` / training pipeline) |
|---|---|
| id / index columns carry no signal | Dropped (`DROP_COLS`) |
| 0 duplicates, 0 train/test overlap | No de-duplication; official test split used as hold-out |
| 57/43 class split | Stratified K-fold; report F1, ROC-AUC, MCC; Dummy baseline for reference |
| Arrival delay NaN (310 rows), r = 0.965 with departure delay | Fill from departure delay. Experiment lab "Missing values": all strategies within 0.003 F1, so the simplest leak-free one is kept |
| Rating 0 = not applicable, informative | Treat 0 as missing -> median of training fold; add `n_unrated` count feature |
| Delays skew ~6.7, distance 1.11 | `log1p` on delays and distance |
| Outliers are genuine | Kept; log1p reduces leverage; scaling only for KNN/SVM/MLP |
| Departure/arrival delays nearly duplicate | Keep both + derived `delay_recovered` (dep - arr), tested in feature experiments |
| Ratings correlated in clusters | Keep all; add `service_mean`; models with bagging / NCA / regularisation |
| Class, travel type, loyalty strongly linked to target | Encoded as ordinal / binary flags; used by the rule baseline |
| Gender near-zero signal | Kept (tested "drop demographics" in Experiment lab) and used in the fairness audit |
| Stable train/test (PSI < 0.1) | Same PSI tool reused for drift checks on new data |
| All fitting done per CV fold | `AirlineFeatures` lives inside each pipeline - no leakage |
